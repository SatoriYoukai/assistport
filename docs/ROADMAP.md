# 演进顺序与验收

已确定定位：Windows 优先，面向个人技术协助与 agent 用户。先完善单次协助的接入、授权、操作与退出，再增加能力扩展。

## 本轮：整理原型

- 独立源码目录，排除实际会话凭据、机器资料、安装包与 node_modules。
- `status` 明确历史状态；`probe` 运行真实认证挑战命令。
- PowerShell 默认关闭进度输出，减少非交互 CLIXML 进度噪声；仍不保证解析所有 stderr 序列化内容。
- 设计理念、信任边界、测试覆盖与贡献约束。
- 大脚本自动 staging：UTF-8 BOM、受限目录、传输后哈希校验、退出码和清理结果；本地真实 PowerShell 测试通过，跨机 VM 待验收。
- Timeout 覆盖握手和执行，失败清理的后续错误不会引发未捕获异常。
- 共用可并发读取的日志诊断函数；runner 不再在退出时发起异步密钥清理。
- 密钥写入前验证私钥可解析且与公钥匹配；Windows CI 配置覆盖 Node.js 22/24，云端执行结果以仓库 Actions 为准。
- 默认 full 完整协助声明、协助者显示标签、接入后信息/停止窗口原型及打包检查。WPF 静态预览通过，桌面任务与停止按钮待 VM 验收。
- 内置截图生命周期及 CLI、图片下载校验、修改归属/PID 校验；外部工具来源登记。生命周期使用隔离的任务替身验证；一台 Windows 11 上的交互任务已完成真实截图与下载，跨环境权限及停止/到期回收仍待验收。
- CLI/JavaScript/MCP 共用 v1 结果和错误码、操作编号、执行完成状态；单会话 stdio MCP 已实现。真实 MCP 客户端、反向 SSH 与 PowerShell 的本地链路测试通过。

## 后续再评估

扩展 manifest 与按需启停；登录用户桌面代理；固定公网入口指南；签名发布、供应链验证及可重复打包；Linux/macOS 支持。

第一版不做无人值守设备资产平台、多租户控制台、杀毒引擎、自研完整远程桌面协议。

## 当前已知限制

- staging 不自动携带脚本关联文件；断线可能遗留脚本，远端进程完成状态仍可能未知。
- `probe` 成功只说明探测时刻可执行；总 timeout 已覆盖握手，但不能保证远端进程被终止。
- 真实电脑在重启/休眠后曾失去通道，恢复原因未核实，不能宣称自动恢复已完整验收。
- 尚无完整命令审计、命令级权限隔离、鼠标键盘控制或外部工具自动部署。MCP stdio 已有原型；内置截图已通过单台实机的单次捕获验证，完整生命周期仍待验收。GUI 是接入后的信息/停止窗口，不增加前置确认，也不充当权限沙箱。
- 操作编号不持久化，不提供幂等去重/断线结果恢复；MCP 单实例拒绝并发，不限制不同 CLI/MCP 进程。文件传输失败可能留下部分文件。
- Windows 系统改动、已执行命令与安装组件不随会话撤销自动回滚；Stop 需另行删除交付包。
- 同一会话修复取消 runner 异步清理后仍需 VM 故障注入验证，包括到期任务与修复同时发生的边界。
