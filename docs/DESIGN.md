# AssistPort 设计理念 v0.1

## 服务谁、解决什么

第一版面向个人技术协助与 agent 用户：帮助亲友处理电脑问题的技术协助者，以及能够调用终端的 agent 用户。目标用户不需要理解隧道、密钥和 MCP：接收包，确认授权，等待协助，随时结束。

产品优先级依次是：目标用户少量操作完成接入，协助者得到可靠的连接证据，agent 使用稳定的机器可读接口，目标用户方便停止。第一版不为专业 IT 团队建设资产管理、多租户控制台或长期值守。

成功标准：协助者能用一个真实命令确认连接，并在不破坏用户现有功能的前提下完成明确任务；结束后接入能力失效，双方能说明做过什么、还留下什么。

## 已确定的接入体验

- 目标用户运行启动命令并同意 UAC 后直接接入，不增加必须点击的授权确认页面。已处于管理员环境时无需再次弹 UAC。
- 接入后自动显示协助者、所选授权范围、有效期、真实连接状态和停止入口。信息窗口提供退出能力，不阻塞连接。
- 首次接入选定本次范围，agent 可以在范围内自行部署、启用及停用需要的能力，不对每个已授权扩展再次弹确认。
- 扩展仍受同一次会话的期限与撤销约束，不能因部署能力而获得永久驻留授权。

范围由协助者生成包时指定，默认“完整协助”：命令、文件、截图和桌面操作。当前只实现 `full` 一档；协助者名称通过 `-OperatorLabel` 提供，是显示标签，不是额外认证。

会话声明及信息窗口原型已实现。Bootstrap 成功后尝试在当前登录用户桌面启动窗口，失败不阻断接入；没有前置确认页面。窗口显示接入环境启动状态，真实连通性仍由协助者 `probe` 验证。窗口自动启动、UAC 停止和权限配置尚待 VM 验收；扩展部署策略、真实连接状态展示及系统级隔离仍待实现。

工具策略已确定为“内置优先，允许添加可信工具”。生命周期见 [CAPABILITIES.md](CAPABILITIES.md)：内置截图原型记录实例归属、验证结果与清理资源；外部工具先登记来源、预期 hash、审核依据及清理步骤，登记与下载/安装/验证分别报告。

## 六条原则

1. **临时性是默认值。** 会话有明确期限，目标主动连接，撤销不能仅改变页面状态。重启恢复只服务于未到期的同一次协助，永久值守不进入第一版。
2. **用户掌握开关。** 运行启动命令与必要的 UAC 是接入入口，随后自动显示权限、期限、接入对象与退出方法。目标用户能够停止，信息显示不额外阻塞接入。授权说明 UI 仍需完善。
3. **接入独立于智能。** 核心不绑定模型、平台、API key 或推理服务。人工 CLI 与不同 agent 共用同一条可验证链路；MCP 只是适配层。
4. **能力逐步增加。** 第一阶段只有命令与文件；需要屏幕、浏览器或桌面输入时，在首次选定范围内由 agent 自行启用扩展。管理员会话目前具有广泛执行能力，不能声称已经实现命令级最小权限。
5. **状态需要证据。** 已安装、已授权、已登记、通道可达、命令成功、任务完成是不同事实。连接成功不代表修复成功。正常窗口展示真实命令与输出，日志不能伪造进度。
6. **变更能解释。** 诊断先于修改；对可疑文件保留来源和隔离依据，保留回滚条件。命令、文件、重启等记录应该可供审阅；审计是待实现能力，不能把当前连接日志当成完整审计。

## 架构与信任

```text
目标用户授权 bootstrap
  └─ 独立 loopback sshd + 回连客户端
       └─ WSS 内 SSH / 直接 TCP SSH → 协助者 receiver
            └─ 固定 loopback 反向端口 → 共用操作实现 → CLI / JavaScript / MCP stdio
```

目标回连的私钥仅能向 receiver 登记身份和申请分配的转发；不能取得 receiver 的普通 shell。协助者控制私钥通过转发登录目标授权账户。目标先固定 receiver 公钥，receiver 在已认证回连中首次接受目标公钥，之后拒绝身份变化。

这仍信任持有包的人就是预期目标。首次登记没有独立的人机确认/配对通道，泄露的未使用包可能被抢先登记。保护包的交付与控制端是必需条件。Cloudflare 终止外层 TLS，内部 SSH 保护命令与文件内容；中间服务仍可观察流量及连接元数据。

控制端与目标授权账户都属于高信任边界。接入层不判断每条命令是否合理；恶意 agent 或被攻陷的控制端可能在授权权限内破坏目标。待设计的操作策略与审批应放在 operator/MCP 层，不能靠提示词充当安全隔离。

安装资源所需的 Windows 提权、远程账户的系统权限、扩展允许范围需要分别表达。当前管理员 SSH 能执行任意账户权限内的命令；后续若只在 operator/MCP 限制扩展工具，就应明确标为接口策略，不能宣称阻止了通过 shell 绕过。真正受限会话需要额外的操作 broker、受限账户或其他系统隔离方案。

## 核心与扩展

| 层 | 负责 | 不纳入该层 |
|---|---|---|
| 会话核心 | 身份、传输、有效期、撤销、重连 | 病毒判断、自动卸载策略 |
| 操作接口 | 命令、文件、结果、未来审计与策略 | 模型推理、自动决定清理对象 |
| 能力扩展 | 桌面、截图、浏览器、诊断工具的生命周期 | 静默扩大权限、无期限驻留 |
| 任务流程 | 诊断、修复、验证、用户说明 | 假装接入就意味着任务完成 |

杀毒软件安装、安全忠告窗口和广告软件清理属于任务流程或示例扩展；具体受助电脑的资料、日志和检测样本不进入源码。

## 开源讨论尚待明确

- 项目名及许可证：AssistPort，MIT。
- 默认授权级别：是否提供无需管理员的受限接入方式？当前 bootstrap 需要管理员。
- 更细范围及受限会话：需要哪些档位、哪些限制必须由系统实施？第一版已选定生成包时声明，默认完整协助。
- 公网入口：Quick Tunnel 降低首次配置成本，固定入口更稳定；保留用户自带入口与 TCP。
- 可见性：信息/停止窗口原型已有，通用真实 PowerShell 命令记录尚待实现；不增加接入前的强制确认页面，不强制全屏、不伪造安全状态。
